# Continuous Claude Desktop Code (CCDC)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Português](README.pt.md) | [Русский](README.ru.md) | **Українська** | [Polski](README.pl.md) | [Nederlands](README.nl.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md) | [Bahasa Indonesia](README.id.md) | [ไทย](README.th.md) | [العربية](README.ar.md) | [हिन्दी](README.hi.md)

Застосунок для області сповіщень Windows, який робить локальні сеанси **Code** у Claude для комп'ютера доступними в будь-якому обліковому записі Claude, у який виконують вхід на цьому ПК.

Неофіційний інструмент; не пов'язаний з компанією Anthropic і не схвалений нею.

## Для кого

CCDC створено для **підприємств, що працюють цілодобово в три зміни**. Кожної зміни за те саме робоче місце (один ПК, один користувач Windows) сідає інша людина й входить у Claude для комп'ютера під власним обліковим записом Claude. Завдяки CCDC наступна зміна після входу продовжує роботу в Code з того місця, де зупинилася попередня.

Тому всі сеанси Code на цьому ПК видно кожному, хто виконує на ньому вхід. Не використовуйте CCDC там, де люди не повинні бачити сеанси одне одного. Якщо ви використовуєте корпоративний обліковий запис (організації), перевірте також правила своєї компанії.

## Яку проблему це розв'язує

Застосунок зберігає **список** сеансів Code в окремій папці для кожного облікового запису та організації:

```
%LOCALAPPDATA%\Claude-Data\claude_<pkg>\claude-code-sessions\<accountUuid>\<orgUuid>\local_<id>.json
```

Самі **розмови** лежать у `~/.claude/projects\...\<cliSessionId>.jsonl` — у місці, спільному для всіх облікових записів. Тому після входу під іншим обліковим записом список сеансів Code виглядає порожнім, хоча розмови досі на диску.

## Як це працює

Застосунок читає свою папку сеансів **лише під час запуску та входу** (під час входу — двічі, у межах приблизно двох секунд). Змусити його пізніше перечитати лише список неможливо. Власний журнал застосунку `%LOCALAPPDATA%\Claude\Logs\main.log` фіксує і виходи, і входи:

- вихід: `[account] Login-state transition (loggedOut: false → true ...)`
- вхід: `[LocalSessionManager] Initialization succeeded — accountId=…, orgId=…`

CCDC стежить за цим журналом і діє так:

1. **Вихід** → найновіша версія кожного сеансу копіюється в усі папки облікових записів/організацій, тож наступний обліковий запис, у який виконають вхід, одразу знайде їх у своїй папці. Копіюються лише ті сеанси, яких у папці немає або які в ній застарілі.
2. **Вхід** → типово копії залишаються на місці. Якщо ввімкнено «Видаляти копії після входу», CCDC чекає, поки застосунок прочитає свій список (6 секунд після останнього рядка про вхід), а потім видаляє копії скрізь, крім папки облікового запису, у який виконано вхід.

Сеанс, видалений у застосунку, видаляється й з інших папок, тому під іншим обліковим записом він не повертається.

Перед копіюванням CCDC перевіряє вільне місце на диску. Якщо місця не вистачає на копії плюс 512 МБ, нічого не копіюється й показується попередження.

### Чому копії зберігаються типово

Зберігати копії — найщадніший для SSD варіант:

- **Копії зберігаються (типово)**: під час першого виходу всі сеанси копіюються один раз. Далі кожен вихід записує лише сеанси, що змінилися з попереднього разу, — зазвичай кілька файлів і кілька МБ — і завершується майже миттєво.
- **Копії видаляються після входу**: кожен вхід видаляє копії, тож кожен вихід мусить записувати їх усі знову. Якщо сеансів близько 300, а папок облікових записів/організацій — 10, це приблизно 600 МБ запису під час кожної передачі зміни, а потім ще видалення близько 3000 файлів.

Ціна цього — місце на диску: копії залишаються й займають приблизно (загальний розмір файлів сеансів × кількість папок облікових записів/організацій).

### Чому не використовуються точки з'єднання та жорсткі посилання

Якби всі папки облікових записів вказували на одну справжню папку, копіювати не довелося б, але застосунок Claude навмисно блокує обидва способи:

- **Точки з'єднання (junctions) та символічні посилання**: перед кожним збереженням застосунок перевіряє, що папка сеансів є справжньою папкою, і відмовляється зберігати, якщо це посилання (`Refusing non-directory at private dir path (symlink/file plant)`). Під час перевірки на реальному застосунку список читався через точку з'єднання, але кожне збереження сеансу чи запланованого завдання завершувалося помилкою, зокрема й для щойно створених сеансів.
- **Жорсткі посилання**: файл, що має більше одного посилання, застосунок вважає небезпечним. Він відмовляється записувати в такі файли й попереджає, коли їх читає. До того ж він зберігає дані так: записує тимчасовий файл і перейменовує його, а це розривало б посилання під час кожного збереження.

Ці перевірки захищають від файлів чи папок, підкинутих ззовні, тож CCDC їх не обходить. Він копіює звичайні файли — такі самі, які записує сам застосунок.

## Вимоги

- Windows 10 або 11 і Claude для комп'ютера (інсталяція MSIX)
- [Node.js](https://nodejs.org) 18 або новіший

## Інсталяція

Завантажте інсталятор у розділі [Releases](../../releases), розпакуйте й запустіть `setup.cmd`. Права адміністратора не потрібні.

- Інсталюється в `%LOCALAPPDATA%\Programs\CCDC`.
- Створює ярлик `Continuous Claude Desktop Code` на робочому столі та в меню «Пуск».
- Відображається в розділі Параметри > Програми > Інстальовані програми як «Continuous Claude Desktop Code (CCDC)»; видалити можна там.
- Запускається в області сповіщень одразу після інсталяції.
- Щоб CCDC запускався під час входу у Windows, інсталюйте його з `setup.cmd /startup`; щоб вимкнути автозапуск, використайте `setup.cmd /nostartup`. Без жодного з цих параметрів повторна інсталяція зберігає попереднє налаштування.
- Повторна інсталяція зупиняє запущений CCDC і замінює його файли; ваші налаштування (`ccdc.json`) зберігаються.
- Після видалення файли сеансів Claude і папка резервних копій CCDC залишаються на місці.

Щоб запускати CCDC безпосередньо з цього репозиторію без інсталяції, запустіть `ccdc-tray.vbs` або скористайтеся командним рядком нижче.

## Застосунок в області сповіщень

В області сповіщень з'являється помаранчева літера **C** (сіра, поки автосинхронізацію вимкнено). Натисніть її, щоб відкрити меню:

| Пункт меню | Що робить |
| --- | --- |
| Рядок стану | Показує, чи стежить CCDC за входами та виходами |
| Автосинхронізація (відстежувати вхід/вихід) | Вмикає або вимикає копіювання та очищення |
| Перенести сеанси в обліковий запис зараз | Збирає всі сеанси в папці одного облікового запису; спершу питає, якщо в цей обліковий запис не виконано вхід |
| Видаляти копії після входу | Типово вимкнено (копії зберігаються; див. вище) |
| Швидкість копіювання/видалення | Швидко (без обмежень), Звичайно (60 МБ/с) або Дбайливо (15 МБ/с). У режимах «Звичайно» і «Дбайливо» видалення обмежене 500 і 100 файлами на секунду |
| Рядок оцінки | Показує, скільки триватиме копіювання під час наступного виходу, а якщо копії видаляються, — і очищення після входу |
| Language | Вибір мови інтерфейсу. Цей пункт завжди підписаний англійською; кожна мова в підменю написана цією мовою |
| Переглянути журнал | Відкриває `%LOCALAPPDATA%\CCDC\watch.log` |
| Назвати облікові записи (ccdc.json) | Відкриває файл налаштувань, щоб дати обліковим записам зрозумілі імена |
| Вийти | Прибирає значок; якщо триває копіювання, спершу чекає його завершення |

Сповіщення з'являються, коли починається копіювання (з орієнтовним часом), коли воно завершене, коли виявлено вхід і коли завершено очищення. За повільнішої швидкості копіювання триває довше, тому наступній людині слід дочекатися сповіщення «Копіювання завершено» (або зачекати приблизно розрахунковий час) і лише тоді входити.

Оцінка обчислюється на основі поточного стану папок і швидкостей копіювання та видалення, виміряних на цьому ПК (зберігаються в `%LOCALAPPDATA%\CCDC\state.json`).

Якщо значка не видно у Windows 11, пошукайте його серед прихованих значків (`^`) на панелі завдань. Щоб він завжди був видимий, увімкніть Windows PowerShell у розділі Параметри > Персоналізація > Панель завдань > Інші значки в області сповіщень.

### Використання пам'яті

Застосунок в області сповіщень сам стежить за журналом Claude, читаючи лише те, що додалося з часу попередньої перевірки. Node.js працює лише під час копіювання чи очищення й після цього завершується, тож між змінами працює тільки застосунок в області сповіщень. У стані простою він приблизно раз на хвилину повертає Windows невикористану пам'ять (використовується близько 15 МБ).

## Налаштування

Налаштування зберігаються в `ccdc.json` у папці програми. Зміни, внесені в меню застосунку, зберігаються в цей файл і діють з наступного копіювання чи очищення без перезапуску.

```json
{
  "keepCopies": true,
  "speed": "fast",
  "language": "",
  "aliases": { "<first 8 characters of an account ID>": "<name>" }
}
```

| Ключ | Значення |
| --- | --- |
| `keepCopies` | `true` (типово): копії зберігаються. `false`: копії видаляються після входу |
| `speed` | `"fast"` (типово), `"normal"`, `"gentle"` |
| `language` | Порожнє значення — використовувати мову Windows; код мови, наприклад `"ja"`, — використовувати цю мову |
| `aliases` | Імена облікових записів, що показуються в меню в області сповіщень |

## Мови

Меню в області сповіщень, сповіщення, попередження та вікна інсталяції/видалення відображаються мовою інтерфейсу Windows або мовою, вибраною в пункті меню **Language**. Підтримуються: англійська, корейська, японська, китайська (спрощена й традиційна), іспанська, французька, німецька, італійська, португальська, російська, українська, польська, нідерландська, турецька, в'єтнамська, індонезійська, тайська, арабська та гінді. Інші мови відображаються англійською.

Усі тексти інтерфейсу містяться в одній таблиці [`locales.csv`](locales.csv): **один рядок — одна мова**, один стовпець — одне повідомлення. Відкрийте її в Excel або Google Таблицях; щоб додати мову, додайте рядок.

- `lang`: назва мовного стандарту Windows (`sv`, `pt-BR`, `zh-Hant`, …). Спочатку використовується рядок, що збігається за мовою й регіоном, потім — за мовою.
- `name`: назва мови цією мовою (`Svenska`); саме її показує меню Language.
- Розриви рядків у клітинці пишіть як `\n` і залишайте `{0}`, `{1}` (туди підставляються числа або імена).
- Порожні клітинки відображаються англійською. Зберігайте файл у форматі CSV UTF-8.

Вивід командного рядка й `watch.log` залишаються англійською, бо їх читає застосунок в області сповіщень.

## Командний рядок

```powershell
node ccdc.mjs status               # app state, settings, sessions per folder, free disk
node ccdc.mjs estimate             # how long the next sign-out copy / sign-in cleanup would take
node ccdc.mjs replicate --dry-run  # what a sign-out copy would write right now
node ccdc.mjs move [--to <acct>]   # gather every session into one account's folder (first 8 characters of the ID are enough)
node ccdc.mjs watch                # follow the app log in the foreground (the tray does this itself)
```

Застосунок в області сповіщень сам запускає такі одноразові завдання: `node ccdc.mjs signout`, `node ccdc.mjs signin --account <id> --org <id>` і `node ccdc.mjs startup` (щоб синхронізуватися з поточним станом Claude під час власного запуску або коли автосинхронізацію вмикають знову).

## Правила для дублікатів

- Якщо сеанс є в кількох папках, пріоритет має копія з найновішим `lastActivityAt`. Копії зберігають час зміни джерела, тому однакові копії розпізнаються за розміром і часом без читання.
- Коли новіша копія замінює файл, старий файл переміщується в `ccdc-backups\<час>\` у папці даних застосунку.
- Сеанси з позначкою `deleted_<id>` не копіюються, а їхні копії в інших папках видаляються.
- Обліковий запис/організація, що входить уперше, ще не має папки, тож під час виходу скопіювати туди нічого не вдалося. У такому разі сеанси з'являться після наступного входу в цей обліковий запис або після перезапуску застосунку.

## Застереження

- CCDC залежить від внутрішньої структури файлів і формулювань журналу Claude для комп'ютера; оновлення застосунку може змінити його поведінку.
- Файли сеансів містять налаштування конекторів (MCP) кожного облікового запису, тож під час відкриття сеансу з іншого облікового запису деякі конектори можуть не підключитися.
- Заплановані завдання не є спільними; кожна папка облікового запису/організації зберігає власні.
- Зміна облікового запису в Claude Code CLI не підтримується. CLI і так може відкрити будь-який сеанс із `~/.claude/projects` за допомогою `--resume`, незалежно від облікового запису.
