# Continuous Claude Desktop Code (CCDC)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Português](README.pt.md) | [Русский](README.ru.md) | **Українська** | [Polski](README.pl.md) | [Nederlands](README.nl.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md) | [Bahasa Indonesia](README.id.md) | [ไทย](README.th.md) | [العربية](README.ar.md) | [हिन्दी](README.hi.md)

Застосунок для області сповіщень, завдяки якому ваші сеанси **Code** у Claude для комп'ютера не зникають, коли ви перемикаєтеся на інший обліковий запис Claude.

Claude для комп'ютера веде окремий список сеансів Code для кожного облікового запису та організації. Увійдіть під іншим обліковим записом — і список виглядатиме порожнім, хоча розмови досі зберігаються на комп'ютері. CCDC копіює сеанси між цими списками, тож хоч би який обліковий запис увійшов наступним, він побачить їх усі.

Неофіційний інструмент; не пов'язаний з компанією Anthropic і не схвалений нею.

**[Завантажити останній випуск](../../releases/latest)** · Windows 10/11 · macOS 11+ · Ubuntu/Debian/Linux Mint · нічого більше інсталювати не потрібно

| Платформа | Версія | Стан |
| --- | --- | --- |
| Windows | 1.0 | Використовується щодня (продовження скриптів 0.3) |
| macOS | 0.1 | Нова; ще не перевірена зі справжнім застосунком Claude на Mac |
| Linux | 0.1 | Нова; інсталяцію перевірено на Debian 12, Ubuntu 24.04 і Linux Mint 22, але ще не зі справжнім застосунком Claude |

## Для кого

- **Спільні комп'ютери та змінна робота.** На підприємстві, що працює цілодобово в три зміни, кожної зміни за те саме робоче місце (один комп'ютер, один системний користувач) сідає інша людина й входить під власним обліковим записом Claude. Завдяки CCDC наступна зміна продовжує роботу в Code з того місця, де зупинилася попередня.
- **Одна людина, кілька облікових записів.** Якщо ви на тому самому комп'ютері перемикаєтеся між особистим і робочим обліковим записом або між організаціями, ваші сеанси Code будуть на місці, хоч би під яким обліковим записом ви увійшли.

Усі сеанси Code на комп'ютері стають видимими для кожного облікового запису, який на ньому входить. Не використовуйте CCDC там, де люди не повинні бачити сеанси одне одного. Якщо ви користуєтеся корпоративним обліковим записом (організації), спершу перевірте правила своєї компанії: CCDC копіює сеанси робочого облікового запису також у папку особистого, і навпаки.

## Яку проблему це розв'язує

Застосунок зберігає **список** сеансів Code в окремій папці для кожного облікового запису та організації:

```
<Claude data folder>/claude-code-sessions/<accountUuid>/<orgUuid>/local_<id>.json
```

| | Папка даних Claude | Журнал Claude |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\Claude-Data\claude_<pkg>` (або `%APPDATA%\Claude`) | `%LOCALAPPDATA%\Claude\Logs\main.log` |
| macOS | `~/Library/Application Support/Claude` | `~/Library/Logs/Claude/main.log` |
| Linux | `~/.config/Claude` | `~/.config/Claude/logs/main.log` |

(Організації, які використовують Claude через власного хмарного провайдера, мають `Claude-3p` замість `Claude`; CCDC шукає й там.)

Самі **розмови** лежать у `~/.claude/projects/.../<cliSessionId>.jsonl` — у місці, спільному для всіх облікових записів. Тому після входу під іншим обліковим записом список сеансів Code виглядає порожнім, хоча розмови досі на диску.

## Як це працює

Застосунок читає свою папку сеансів **лише під час запуску та входу** (під час входу — двічі, у межах приблизно двох секунд). Змусити його пізніше перечитати лише список неможливо. Власний журнал застосунку фіксує обидві події:

- вихід: `[account] Login-state transition (loggedOut: false → true ...)`
- вхід: `[LocalSessionManager] Initialization succeeded — accountId=…, orgId=…`

CCDC стежить за цим журналом і діє так:

1. **Вихід** → найновіша версія кожного сеансу копіюється в усі папки облікових записів/організацій, тож наступний обліковий запис, у який виконають вхід, одразу знайде їх у своїй папці. Копіюються лише ті сеанси, яких у папці немає або які в ній застарілі.
2. **Вхід** → типово копії залишаються на місці. Якщо ввімкнено «Видаляти копії після входу», CCDC чекає, поки застосунок прочитає свій список (6 секунд після останнього рядка про вхід), а потім видаляє копії скрізь, крім папки облікового запису, у який виконано вхід.

Сеанс, видалений у застосунку, видаляється й з інших папок, тому під іншим обліковим записом він не повертається.

Перед копіюванням CCDC перевіряє вільне місце на диску. Якщо місця не вистачає на копії плюс 512 МБ, нічого не копіюється й показується попередження.

### Чому копії зберігаються типово

Зберігати копії — найщадніший для SSD варіант:

- **Копії зберігаються (типово)**: під час першого виходу всі сеанси копіюються один раз. Далі кожен вихід записує лише сеанси, що змінилися з попереднього разу, — зазвичай кілька файлів і кілька МБ — і завершується майже миттєво.
- **Копії видаляються після входу**: кожен вхід видаляє копії, тож кожен вихід мусить записувати їх усі знову. Якщо сеансів близько 300, а папок облікових записів/організацій — 10, це приблизно 600 МБ запису під час кожної передачі зміни, а потім ще видалення близько 3000 файлів.

Ціна цього — місце на диску: копії залишаються й займають приблизно (загальний розмір файлів сеансів × кількість папок облікових записів/організацій).

### Чому не використовуються точки з'єднання та жорсткі посилання

Якби всі папки облікових записів вказували на одну справжню папку, копіювати не довелося б, але застосунок Claude навмисно блокує обидва способи:

- **Точки з'єднання (junctions) та символічні посилання**: перед кожним збереженням застосунок перевіряє, що папка сеансів є справжньою папкою, і відмовляється зберігати, якщо це посилання (`Refusing non-directory at private dir path (symlink/file plant)`). Під час перевірки на реальному застосунку список читався через точку з'єднання, але кожне збереження сеансу чи запланованого завдання завершувалося помилкою, зокрема й для щойно створених сеансів.
- **Жорсткі посилання**: файл, що має більше одного посилання, застосунок вважає небезпечним. Він відмовляється записувати в такі файли й попереджає, коли їх читає. До того ж він зберігає дані так: записує тимчасовий файл і перейменовує його, а це розривало б посилання під час кожного збереження.

Ці перевірки захищають від файлів чи папок, підкинутих ззовні, тож CCDC їх не обходить. Він копіює звичайні файли — такі самі, які записує сам застосунок.

## Інсталяція

Завантажте файл для своєї системи в розділі [Releases](../../releases). Файли не мають цифрового підпису (див. [нижче](#про-попередження-системи-безпеки)).

**Windows** — запустіть `CCDC-<version>-windows-x64.msi`. Права адміністратора не потрібні.

- Інсталюється в `%LOCALAPPDATA%\Programs\CCDC`, створює ярлик `Continuous Claude Desktop Code` на робочому столі та в меню «Пуск» і запускає CCDC в області сповіщень.
- Запускається разом із комп'ютером; вимкнути це можна пунктом «Запускати разом із комп'ютером» у меню в області сповіщень.
- Оновлення: запустіть новіший `.msi`. Він закриє CCDC, замінить його й запустить знову; ваші налаштування збережуться.
- Видалити можна в розділі Параметри > Програми > Інстальовані програми > «Continuous Claude Desktop Code (CCDC)».
- Якщо ви користувалися скриптами 0.3, просто інсталюйте `.msi`. Під час першого запуску CCDC зупинить стару версію, збереже її налаштування та імена облікових записів і видалить її.

**macOS** — відкрийте `CCDC-<version>-macos-universal.dmg`, перетягніть **CCDC** у папку «Програми» й запустіть його. На панелі меню з'явиться літера **C**. CCDC запускається разом із комп'ютером, якщо ви не вимкнете це в його меню. Працює на Apple Silicon та Intel.

**Linux** (Ubuntu 22.04+, Debian 12+, Linux Mint 21+, x86_64):

```sh
sudo apt install ./CCDC-<version>-linux-amd64.deb
```

Потім запустіть **Continuous Claude Desktop Code** з меню застосунків. CCDC запускається разом із комп'ютером, якщо ви не вимкнете це в його меню. У GNOME без розширення AppIndicator значок в області сповіщень не відображається (в Ubuntu та Linux Mint це розширення є).

Після видалення файли сеансів Claude, налаштування CCDC і папка резервних копій залишаються на місці.

### Про попередження системи безпеки

Для підпису потрібен платний сертифікат, виданий на конкретну людину або компанію, а CCDC — невеликий безкоштовний проєкт, тому завантажувані файли не підписано. Під час першого запуску система вас попередить; це означає лише, що видавця не перевірено, а не що знайдено щось шкідливе.

CCDC не містить нічого шкідливого. Він не підключається до інтернету, не збирає дані й нічого не змінює поза папками сеансів застосунку Claude та власною папкою. Увесь код міститься в цьому репозиторії, а файли випусків збирає з нього GitHub Actions, журнали якого загальнодоступні. Завантажений файл можна звірити з `SHA256SUMS.txt` у випуску або [зібрати програму самостійно](#збирання).

- **Windows**: якщо SmartScreen показує повідомлення «Windows захистила ваш комп'ютер», натисніть **Докладніше**, а потім **Усе одно запустити**.
- **macOS**: якщо macOS повідомляє, що не може перевірити застосунок, відкрийте **Системні параметри > Приватність і безпека**, прокрутіть униз і натисніть **Усе одно відкрити** поруч із CCDC. (Або виконайте в Терміналі `xattr -dr com.apple.quarantine /Applications/CCDC.app`.)
- **Linux**: пакети `.deb` так не перевіряються.

## Застосунок в області сповіщень

В області сповіщень або на панелі меню з'являється помаранчева літера **C** (сіра, поки автосинхронізацію вимкнено). Натисніть її, щоб відкрити меню:

| Пункт меню | Що робить |
| --- | --- |
| Рядок стану | Показує, чи стежить CCDC за входами та виходами |
| Автосинхронізація (відстежувати вхід/вихід) | Вмикає або вимикає копіювання та очищення |
| Перенести сеанси в обліковий запис зараз | Збирає всі сеанси в папці одного облікового запису; спершу питає, якщо в цей обліковий запис не виконано вхід |
| Видаляти копії після входу | Типово вимкнено (копії зберігаються; див. вище) |
| Швидкість копіювання/видалення | Швидко (без обмежень), Звичайно (60 МБ/с) або Дбайливо (15 МБ/с). У режимах «Звичайно» і «Дбайливо» видалення обмежене 500 і 100 файлами на секунду |
| Рядок оцінки | Показує, скільки триватиме копіювання під час наступного виходу, а якщо копії видаляються, — і очищення після входу |
| Запускати разом із комп'ютером | Запускає CCDC, коли ви входите в систему на комп'ютері |
| Language | Вибір мови інтерфейсу. Цей пункт завжди підписаний англійською; кожна мова в підменю написана цією мовою |
| Переглянути журнал | Відкриває `watch.log` CCDC |
| Назвати облікові записи (ccdc.json) | Відкриває файл налаштувань, щоб дати обліковим записам зрозумілі імена |
| Вийти | Прибирає значок; якщо триває копіювання, спершу чекає його завершення |

Сповіщення з'являються, коли починається копіювання (з орієнтовним часом), коли воно завершене, коли виявлено вхід і коли завершено очищення. За повільнішої швидкості копіювання триває довше, тому наступній людині слід дочекатися сповіщення «Копіювання завершено» (або зачекати приблизно розрахунковий час) і лише тоді входити.

Оцінка обчислюється на основі поточного стану папок і швидкостей копіювання та видалення, виміряних на цьому комп'ютері (зберігаються в `state.json` у папці CCDC).

Якщо значка не видно у Windows 11, пошукайте його серед прихованих значків (`^`) на панелі завдань. Щоб він завжди був видимий, увімкніть CCDC у розділі Параметри > Персоналізація > Панель завдань > Інші значки в області сповіщень.

CCDC — це одна нативна програма розміром близько 1 МБ. В очікуванні вона щопівсекунди читає лише те, що додалося до журналу Claude з часу попередньої перевірки, і сама використовує близько 4 МБ пам'яті.

## Налаштування

Налаштування зберігаються в `ccdc.json` у папці CCDC:

| | Папка CCDC |
| --- | --- |
| Windows | `%LOCALAPPDATA%\CCDC` |
| macOS | `~/Library/Application Support/CCDC` |
| Linux | `~/.config/ccdc` |

Зміни, внесені в меню в області сповіщень, зберігаються в цей файл і діють з наступного копіювання чи очищення без перезапуску. `watch.log` і `state.json` лежать у тій самій папці.

```json
{
  "keepCopies": true,
  "speed": "fast",
  "language": "",
  "startAtLogin": true,
  "aliases": { "<first 8 characters of an account ID>": "<name>" }
}
```

| Ключ | Значення |
| --- | --- |
| `keepCopies` | `true` (типово): копії зберігаються. `false`: копії видаляються після входу |
| `speed` | `"fast"` (типово), `"normal"`, `"gentle"` |
| `language` | Порожнє значення — використовувати мову системи; код мови, наприклад `"ja"`, — використовувати цю мову |
| `startAtLogin` | Задається пунктом «Запускати разом із комп'ютером» у меню в області сповіщень |
| `aliases` | Імена облікових записів, що показуються в меню в області сповіщень |
| `dataDir`, `appLog` | Повні шляхи до папки даних і журналу Claude — лише якщо CCDC не може знайти їх самостійно |

## Мови

Меню в області сповіщень, сповіщення та попередження відображаються мовою інтерфейсу системи або мовою, вибраною в пункті меню **Language**. Підтримуються: англійська, корейська, японська, китайська (спрощена й традиційна), іспанська, французька, німецька, італійська, португальська, російська, українська, польська, нідерландська, турецька, в'єтнамська, індонезійська, тайська, арабська та гінді. Інші мови відображаються англійською.

Усі тексти інтерфейсу містяться в одній таблиці [`locales.csv`](locales.csv), вбудованій у програму: **один рядок — одна мова**, один стовпець — одне повідомлення. Відкрийте її в Excel або Google Таблицях; щоб додати мову, додайте рядок і [зберіть](#збирання) CCDC.

- `lang`: мовний тег (`sv`, `pt-BR`, `zh-Hant`, …). Спочатку використовується рядок, що збігається за мовою й регіоном, потім — за мовою.
- `name`: назва мови цією мовою (`Svenska`); саме її показує меню Language.
- Розриви рядків у клітинці пишіть як `\n` і залишайте `{0}`, `{1}` (туди підставляються числа або імена).
- Порожні клітинки відображаються англійською. Зберігайте файл у форматі CSV UTF-8.

Вивід командного рядка й `watch.log` залишаються англійською.

## Командний рядок

Та сама програма працює й у терміналі (у Windows це `ccdc.exe` у `%LOCALAPPDATA%\Programs\CCDC`; у macOS — `/Applications/CCDC.app/Contents/MacOS/ccdc`):

```sh
ccdc status               # app state, settings, sessions per folder, free disk
ccdc estimate             # how long the next sign-out copy / sign-in cleanup would take
ccdc replicate --dry-run  # what a sign-out copy would write right now
ccdc move [--to <acct>]   # gather every session into one account's folder (first 8 characters of the ID are enough)
ccdc watch                # follow the Claude log in the foreground, without the tray
ccdc version
```

Параметри `--data-dir <path>` і `--app-log <path>` дають змогу вручну вказати папку даних або журнал Claude.

## Правила для дублікатів

- Якщо сеанс є в кількох папках, пріоритет має копія з найновішим `lastActivityAt`. Копії зберігають час зміни джерела, тому однакові копії розпізнаються за розміром і часом без читання.
- Коли новіша копія замінює файл, старий файл переміщується в `ccdc-backups/<time>/` у папці даних Claude.
- Сеанси з позначкою `deleted_<id>` не копіюються, а їхні копії в інших папках видаляються.
- Обліковий запис/організація, що входить уперше, ще не має папки, тож під час виходу скопіювати туди нічого не вдалося. У такому разі сеанси з'являться після наступного входу в цей обліковий запис або після перезапуску застосунку.

## Застереження

- CCDC залежить від внутрішньої структури файлів і формулювань журналу Claude для комп'ютера; оновлення застосунку може змінити його поведінку.
- Файли сеансів містять налаштування конекторів (MCP) кожного облікового запису, тож під час відкриття сеансу з іншого облікового запису деякі конектори можуть не підключитися.
- Заплановані завдання не є спільними; кожна папка облікового запису/організації зберігає власні.
- Зміна облікового запису в Claude Code CLI не підтримується. CLI і так може відкрити будь-який сеанс із `~/.claude/projects` за допомогою `--resume`, незалежно від облікового запису.

## Збирання

CCDC написано мовою Rust; [інсталюйте Rust](https://rustup.rs), а потім виконайте:

```sh
cargo build --release                                    # the program (target/release/ccdc)
powershell -File packaging\windows\build-msi.ps1         # Windows .msi (needs the .NET SDK)
sh packaging/macos/make-dmg.sh                           # macOS .dmg (on a Mac)
sh packaging/linux/build-deb.sh                          # Linux .deb (on Ubuntu 22.04, or in Docker:)
docker run --rm -v "$PWD:/w" -w /w ubuntu:22.04 sh packaging/linux/build-deb.sh
```

Версія для кожної платформи задається в `[package.metadata.ccdc]` у `Cargo.toml`. GitHub Actions ([`.github/workflows/build.yml`](.github/workflows/build.yml)) збирає всі три під час кожного push, а для тегу `v*` додає їх до чернетки випуску.
