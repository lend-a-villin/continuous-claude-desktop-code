# Continuous Claude Desktop Code (CCDC)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-Hans.md) | [繁體中文](README.zh-Hant.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Português](README.pt.md) | **Русский** | [Українська](README.uk.md) | [Polski](README.pl.md) | [Nederlands](README.nl.md) | [Türkçe](README.tr.md) | [Tiếng Việt](README.vi.md) | [Bahasa Indonesia](README.id.md) | [ไทย](README.th.md) | [العربية](README.ar.md) | [हिन्दी](README.hi.md)

Приложение для области уведомлений, которое сохраняет ваши сеансы **Code** из Claude для компьютера, когда вы переключаетесь между учётными записями Claude.

Claude для компьютера ведёт отдельный список сеансов Code для каждой учётной записи и организации. Стоит войти под другой учётной записью — и список выглядит пустым, хотя беседы по-прежнему лежат на компьютере. CCDC копирует сеансы между папками, поэтому любая учётная запись, в которую выполнят вход следующей, видит их все.

Неофициальный инструмент; не связан с компанией Anthropic и не одобрен ею.

## Для кого

- **Общие компьютеры и сменная работа.** На предприятии, работающем круглосуточно в три смены, в каждую смену за одно и то же рабочее место (один компьютер, один пользователь системы) садится другой человек и входит под своей учётной записью Claude. Благодаря CCDC следующая смена продолжает работу в Code с того места, где остановилась предыдущая.
- **Один человек, несколько учётных записей.** Если вы переключаетесь на одном компьютере между личной и рабочей учётной записью или между организациями, ваши сеансы Code будут на месте, под какой бы учётной записью вы ни вошли.

Все сеансы Code на компьютере становятся видны каждой учётной записи, под которой на нём выполняют вход. Не используйте CCDC там, где люди не должны видеть сеансы друг друга. Если вы используете корпоративную учётную запись (организации), сначала сверьтесь с правилами своей компании: CCDC копирует сеансы рабочей учётной записи и в папку личной, и наоборот.

## Какую проблему он решает

Приложение для компьютера хранит **список** сеансов Code в отдельной папке для каждой учётной записи и организации:

```
<Claude data folder>/claude-code-sessions/<accountUuid>/<orgUuid>/local_<id>.json
```

| | Папка данных Claude | Журнал Claude |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\Claude-Data\claude_<pkg>` (или `%APPDATA%\Claude`) | `%LOCALAPPDATA%\Claude\Logs\main.log` |
| macOS | `~/Library/Application Support/Claude` | `~/Library/Logs/Claude/main.log` |
| Linux | `~/.config/Claude` | `~/.config/Claude/logs/main.log` |

(Организации, которые используют Claude через собственного облачного провайдера, работают с `Claude-3p` вместо `Claude`; CCDC проверяет и эту папку.)

Сами **беседы** лежат в `~/.claude/projects/.../<cliSessionId>.jsonl`, общем для всех учётных записей. Поэтому после входа под другой учётной записью список сеансов Code выглядит пустым, хотя беседы остаются на диске.

## Как это работает

Приложение читает свою папку сеансов **только при запуске и при входе** (при входе — дважды, примерно за две секунды). Заставить его позже перечитать только список нельзя. Журнал самого приложения фиксирует оба события:

- выход: `[account] Login-state transition (loggedOut: false → true ...)`
- вход: `[LocalSessionManager] Initialization succeeded — accountId=…, orgId=…`

CCDC следит за этим журналом и действует так:

1. **Выход** → самая новая версия каждого сеанса копируется во все папки учётных записей/организаций, так что следующая учётная запись, в которую выполнят вход, сразу найдёт их в своей папке. Копируются только сеансы, которых в папке нет или которые в ней устарели.
2. **Вход** → по умолчанию копии остаются на месте. Если включён пункт «Удалять копии после входа», CCDC ждёт, пока приложение прочитает список (6 секунд после последней строки о входе), и затем удаляет копии везде, кроме папки вошедшей учётной записи.

Сеанс, удалённый в приложении, удаляется и из остальных папок, поэтому он не появится снова под другой учётной записью.

Перед копированием CCDC проверяет свободное место на диске. Если его не хватает на копии плюс 512 МБ, ничего не копируется и показывается предупреждение.

### Почему копии сохраняются по умолчанию

Сохранение копий — самый щадящий для SSD вариант:

- **Копии сохраняются (по умолчанию)**: первый выход копирует все сеансы один раз. Дальше каждый выход записывает только сеансы, изменившиеся с прошлого раза, — обычно несколько файлов и несколько МБ, — и завершается почти мгновенно.
- **Копии удаляются после входа**: каждый вход удаляет копии, поэтому при каждом выходе приходится записывать их все заново. При примерно 300 сеансах и 10 папках учётных записей/организаций это около 600 МБ записи при каждой пересменке, а потом ещё удаление около 3000 файлов.

Платой за это служит место на диске: копии остаются и занимают примерно (общий размер файлов сеансов × число папок учётных записей/организаций).

### Почему не точки соединения и не жёсткие ссылки

Если бы все папки учётных записей указывали на одну настоящую папку, копировать было бы не нужно, но приложение Claude намеренно блокирует оба способа:

- **Точки соединения и символические ссылки**: перед каждым сохранением приложение проверяет, что папка сеансов — настоящая папка, и отказывается сохранять, если это ссылка (`Refusing non-directory at private dir path (symlink/file plant)`). При проверке на реальном приложении список читался через точку соединения, но каждое сохранение сеанса и запланированной задачи завершалось ошибкой, включая сохранение совсем новых сеансов.
- **Жёсткие ссылки**: файл, у которого больше одной ссылки, приложение считает небезопасным. Оно отказывается записывать в такие файлы и выдаёт предупреждение при их чтении. Кроме того, оно сохраняет файлы так: записывает временный файл и переименовывает его, а это разрывало бы ссылку при каждом сохранении.

Эти проверки защищают от файлов и папок, подложенных извне, поэтому CCDC их не обходит. Он копирует обычные файлы — такие же, какие записывает само приложение.

## Установка

Скачайте файл для своей системы в разделе [Releases](../../releases). Файлы не подписаны цифровой подписью (см. [ниже](#о-предупреждении-безопасности)).

**Windows** — запустите `CCDC-<version>-windows-x64.msi`. Права администратора не нужны.

- Устанавливается в `%LOCALAPPDATA%\Programs\CCDC`, создаёт ярлык `Continuous Claude Desktop Code` на рабочем столе и в меню «Пуск» и запускает CCDC в области уведомлений.
- Запускается вместе с компьютером; отключить это можно пунктом «Запускать вместе с компьютером» в меню значка.
- Обновление: запустите более новый `.msi`. Он закроет CCDC, заменит его и снова запустит; ваши настройки сохранятся.
- Удалить можно в разделе Параметры > Приложения > Установленные приложения > «Continuous Claude Desktop Code (CCDC)».
- Если у вас стоят скрипты версии 0.3, просто установите `.msi`. При первом запуске CCDC остановит старую версию, сохранит её настройки и имена учётных записей и удалит её.

**macOS** — откройте `CCDC-<version>-macos-universal.dmg`, перетащите **CCDC** в папку «Программы» и запустите. В строке меню появится буква **C**. Приложение запускается вместе с компьютером, если не отключить это в его меню. Работает на Apple Silicon и Intel.

**Linux** (Ubuntu 22.04+, Debian 12+, Linux Mint 21+, x86_64):

```sh
sudo apt install ./CCDC-<version>-linux-amd64.deb
```

Затем запустите **Continuous Claude Desktop Code** из меню приложений. Оно запускается вместе с компьютером, если не отключить это в его меню. В GNOME без расширения AppIndicator значок в области уведомлений не отображается (в Ubuntu и Linux Mint оно есть).

После удаления файлы сеансов Claude, настройки CCDC и папка резервных копий остаются на месте.

### О предупреждении безопасности

Для подписи нужен платный сертификат, привязанный к человеку или компании, а CCDC — небольшой бесплатный проект, поэтому загружаемые файлы не подписаны. При первом запуске система выдаст предупреждение; оно означает лишь, что издатель не проверен, а не что найдено что-то вредоносное.

В CCDC нет ничего вредоносного. Он не подключается к интернету, не собирает данные и ничего не меняет за пределами папок сеансов приложения Claude и своей собственной папки. Весь код находится в этом репозитории, а файлы выпусков собираются из него в GitHub Actions, журналы которых открыты. Вы можете сверить загруженный файл с `SHA256SUMS.txt` в выпуске или [собрать программу сами](#сборка).

- **Windows**: если SmartScreen сообщает «Система Windows защитила ваш компьютер», нажмите **Подробнее**, а затем **Выполнить в любом случае**.
- **macOS**: если macOS сообщает, что не может проверить приложение, откройте **Системные настройки > Конфиденциальность и безопасность**, прокрутите вниз и нажмите **Всё равно открыть** рядом с CCDC. (Или выполните в Терминале `xattr -dr com.apple.quarantine /Applications/CCDC.app`.)
- **Linux**: пакеты `.deb` так не проверяются.

## Приложение в области уведомлений

В области уведомлений или в строке меню появляется оранжевая буква **C** (серая, пока автосинхронизация выключена). Нажмите на неё, чтобы открыть меню:

| Пункт меню | Что делает |
| --- | --- |
| Строка состояния | Показывает, следит ли CCDC за входами и выходами |
| Автосинхронизация (отслеживать вход/выход) | Включает или выключает копирование и очистку |
| Перенести сеансы в учётную запись сейчас | Собирает все сеансы в папке одной учётной записи; спрашивает подтверждение, если в неё не выполнен вход |
| Удалять копии после входа | По умолчанию выключено (копии сохраняются; см. выше) |
| Скорость копирования/удаления | Быстро (без ограничений), Обычно (60 МБ/с) или Бережно (15 МБ/с). В режимах «Обычно» и «Бережно» удаление ограничено 500 и 100 файлами в секунду |
| Строка оценки | Показывает, сколько займёт копирование при следующем выходе, а если копии удаляются — и очистка после входа |
| Запускать вместе с компьютером | Запускает CCDC, когда вы входите в систему на компьютере |
| Language | Выбирает язык интерфейса. Этот пункт всегда подписан по-английски; каждый язык в подменю написан на этом языке |
| Открыть журнал | Открывает `watch.log` CCDC |
| Назвать учётные записи (ccdc.json) | Открывает файл настроек, чтобы дать учётным записям понятные имена |
| Выход | Убирает значок; если идёт копирование, сначала дожидается его завершения |

Уведомления появляются, когда начинается копирование (с оценкой времени), когда оно завершено, когда обнаружен вход и когда завершена очистка. При медленной скорости копирование длится дольше, поэтому следующему человеку нужно дождаться уведомления «Копирование завершено» (или выждать примерно расчётное время) и только потом входить.

Оценка рассчитывается по текущему состоянию папок и по скорости копирования и удаления, измеренной на этом компьютере (хранится в `state.json` в папке CCDC).

Если значок не виден в Windows 11, проверьте скрытые значки (`^`) на панели задач. Чтобы он всегда был виден, включите CCDC в разделе Параметры > Персонализация > Панель задач > Другие значки в области уведомлений.

CCDC — одна нативная программа размером около 1 МБ. В режиме ожидания она каждые полсекунды читает только то, что добавилось в журнал Claude с прошлой проверки, и сама использует около 4 МБ памяти.

## Настройки

Настройки хранятся в `ccdc.json` в папке CCDC:

| | Папка CCDC |
| --- | --- |
| Windows | `%LOCALAPPDATA%\CCDC` |
| macOS | `~/Library/Application Support/CCDC` |
| Linux | `~/.config/ccdc` |

Изменения, сделанные в меню значка, сохраняются в этот файл и применяются со следующего копирования или очистки без перезапуска. В той же папке находятся `watch.log` и `state.json`.

```json
{
  "keepCopies": true,
  "speed": "fast",
  "language": "",
  "startAtLogin": true,
  "aliases": { "<first 8 characters of an account ID>": "<name>" }
}
```

| Ключ | Значения |
| --- | --- |
| `keepCopies` | `true` (по умолчанию): копии сохраняются. `false`: копии удаляются после входа |
| `speed` | `"fast"` (по умолчанию), `"normal"`, `"gentle"` |
| `language` | Пустая строка — использовать язык системы; код языка, например `"ja"`, — использовать этот язык |
| `startAtLogin` | Задаётся пунктом «Запускать вместе с компьютером» в меню значка |
| `aliases` | Имена учётных записей, показываемые в меню значка |
| `dataDir`, `appLog` | Только если CCDC не находит папку данных или журнал Claude сам: полные пути к ним |

## Языки

Меню значка, уведомления и предупреждения отображаются на языке интерфейса системы или на языке, выбранном в пункте меню **Language**. Поддерживаются: английский, корейский, японский, китайский (упрощённый и традиционный), испанский, французский, немецкий, итальянский, португальский, русский, украинский, польский, нидерландский, турецкий, вьетнамский, индонезийский, тайский, арабский и хинди. Остальные языки отображаются по-английски.

Все тексты интерфейса находятся в одной таблице [`locales.csv`](locales.csv), встроенной в программу: **одна строка — один язык**, один столбец — одно сообщение. Откройте её в Excel или Google Таблицах; чтобы добавить язык, добавьте строку и [соберите](#сборка) CCDC.

- `lang`: языковой тег (`sv`, `pt-BR`, `zh-Hant`, …). Сначала используется строка, совпадающая по языку и региону, затем — по языку.
- `name`: название языка на этом языке (`Svenska`); его показывает меню Language.
- Переносы строк внутри ячейки пишите как `\n` и сохраняйте `{0}`, `{1}` (туда подставляются числа или имена).
- Пустые ячейки отображаются по-английски. Сохраняйте файл в формате CSV UTF-8.

Вывод командной строки и `watch.log` остаются на английском.

## Командная строка

Та же программа работает и из терминала (в Windows — `ccdc.exe` в `%LOCALAPPDATA%\Programs\CCDC`, в macOS — `/Applications/CCDC.app/Contents/MacOS/ccdc`):

```sh
ccdc status               # app state, settings, sessions per folder, free disk
ccdc estimate             # how long the next sign-out copy / sign-in cleanup would take
ccdc replicate --dry-run  # what a sign-out copy would write right now
ccdc move [--to <acct>]   # gather every session into one account's folder (first 8 characters of the ID are enough)
ccdc watch                # follow the Claude log in the foreground, without the tray
ccdc version
```

С помощью `--data-dir <path>` и `--app-log <path>` можно вручную указать папку данных или журнал Claude.

## Правила для дубликатов

- Если сеанс есть в нескольких папках, приоритет имеет копия с самым новым `lastActivityAt`. Копии сохраняют время изменения источника, поэтому одинаковые копии распознаются по размеру и времени без чтения.
- Когда более новая копия заменяет файл, старый файл перемещается в `ccdc-backups/<time>/` в папке данных Claude.
- Сеансы с отметкой `deleted_<id>` не копируются, а их копии в других папках удаляются.
- У учётной записи/организации, которая входит впервые, ещё нет папки, поэтому при выходе скопировать туда ничего не удалось. В этом случае сеансы появятся после следующего входа в эту учётную запись или после перезапуска приложения.

## Ограничения

- CCDC зависит от внутренней структуры файлов и формулировок журнала Claude для компьютера; обновление приложения может изменить его поведение.
- Файлы сеансов содержат настройки коннекторов (MCP) каждой учётной записи, поэтому при открытии сеанса из другой учётной записи некоторые коннекторы могут не подключиться.
- Запланированные задачи не передаются между учётными записями; в каждой папке учётной записи/организации они свои.
- Смена учётной записи в Claude Code CLI не поддерживается. CLI и так может открыть любой сеанс из `~/.claude/projects` с помощью `--resume`, независимо от учётной записи.

## Сборка

CCDC написан на Rust; [установите Rust](https://rustup.rs), а затем выполните:

```sh
cargo build --release                                    # the program (target/release/ccdc)
powershell -File packaging\windows\build-msi.ps1         # Windows .msi (needs the .NET SDK)
sh packaging/macos/make-dmg.sh                           # macOS .dmg (on a Mac)
sh packaging/linux/build-deb.sh                          # Linux .deb (on Ubuntu 22.04, or in Docker:)
docker run --rm -v "$PWD:/w" -w /w ubuntu:22.04 sh packaging/linux/build-deb.sh
```

Версия для каждой платформы задаётся в `[package.metadata.ccdc]` в `Cargo.toml`. GitHub Actions ([`.github/workflows/build.yml`](.github/workflows/build.yml)) собирает все три при каждом push, а для тега `v*` прикрепляет их к черновику выпуска.
